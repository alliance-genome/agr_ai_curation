# Best practices for AI curation

Give the AI the curation decisions it cannot infer from a paper: the scope of the task, what counts as a record, and your group's conventions. Review its results against the evidence before using them.

## Define one record

For custom extraction, decide when two observations belong together and when they need separate records. For example:

> Extract one record per distinct Drosophila stock used in this paper. Include stocks obtained from stock centers, shared by another lab, or generated by the authors. Combine repeated mentions of the same stock. Exclude background-only mentions.

A different task might need one record per gene, experimental comparison, tissue, and time point. State those boundaries before adding fields. A clear record definition helps prevent duplicate records and unrelated details being combined.

## Put instructions where they apply

| Location | What to write |
|----------|---------------|
| Flow **Initial Instructions** | The overall task for this run |
| Workshop **Prompt** | Reusable extraction guidance for this agent |
| **Additional guidance for this item type** | What counts as an item, and what to include or exclude |
| **Instructions for this detail** | How to collect or interpret one answer |
| Flow **Instructions for this step** | A change in scope for this flow's use of the agent |
| Output step **Output instructions** | Columns, order, row grouping, and presentation |

The AI receives the item-type description and detail instructions in addition to the agent prompt. You do not need to repeat the whole prompt in each place. Keep the instructions consistent; a prompt cannot add fields to a fixed output structure or bypass its validation rules.

## Use details the paper can support

Start with the few details you need. For a stock inventory, **Stock name** and optional **Source** may be enough. If you need a supplier and catalog number kept together, put them in one answer with two parts.

Choose **Always include** only when a part must appear whenever its parent answer appears. If the paper may omit the information, decide whether to allow an empty answer or leave the detail optional. The AI should never invent a value to satisfy a required field.

Use names a colleague would recognize. Add instructions when a name is ambiguous: “Source” could mean a stock center, a donating laboratory, or a citation. See [custom output structures](CUSTOM_OUTPUT_STRUCTURES.md) for examples and settings.

## Give biological context

Include the organism, identifier namespace, or ontology when these affect interpretation:

- “Resolve these C. elegans gene symbols against Alliance records: daf-16, lin-3, unc-54.”
- “Map the anatomy labels to WormBase anatomy terms (WBbt), and retain unresolved labels for review.”
- “Retrieve existing GO annotations for human TP53 with experimental evidence codes.”
- “Look up cytidine in ChEBI and return its identifier and synonyms.”

Retrieving existing annotations differs from proposing new annotations from a paper. Say which you want, and choose an agent that supports that task.

## Choose extraction fields before output columns

A formatter can arrange information that the extraction collected. It cannot reliably supply a missing measurement because a CSV column asks for it.

If a pre-made extractor does not include your required fields, ask AI Chat whether to use a custom extractor. For example, a request for reported fold-change values and experimental/reference comparisons may need a different structure from a packaged expression-pattern format.

For spreadsheet output, specify one row's meaning and the desired columns:

> One row per stock. Put Stock name first and Source second. Leave an unreported source blank. Include supporting evidence.

Use JSON when you need to preserve grouped details. CSV and TSV are useful for tables, but a downloaded file is not automatically a valid submission file.

## Use validators for the questions they can answer

Attach a compatible validator when you need database or ontology resolution. A gene validator resolves gene identity; it does not prove that a gene was used in an experiment. An allele description such as “Ccr2 knockout” may match several records and remain unresolved.

**Validator attached: Yes** describes the configuration. After extraction, read the actual findings. Distinguish a confirmed identity, ambiguous candidates, no match, and a lookup that could not run. If no compatible validator is offered for a detail, review that detail yourself; renaming a field does not give it validation support.

## Build and test a flow in small steps

1. Agree on the initial task with AI Chat.
2. Choose an extractor whose fields fit, or create a custom one.
3. Review validation choices and add an output with explicit formatting instructions.
4. Apply the proposed edits, then save the agent and flow as needed.
5. Run one representative paper and compare the results with your expected records before starting a batch.

**Verify with AI Chat** can help find configuration problems. It does not run the paper or certify extraction accuracy. Saved settings improve consistency, but AI answers can still vary between runs.

## Review and report specific problems

Check record boundaries, omitted observations, source associations, identifiers, and supporting passages. The audit panel shows tool activity; it is not proof that every conclusion is correct.

Use the response's **three-dot menu (⋮)** for feedback. A useful report says what you asked for, what happened, and what should have happened:

> The stock in Table 2 was assigned the supplier from the following row. These are two different stocks; each should keep its own source.

Include your group's convention if it explains the expected result. **Open in Agent Studio** lets AI Chat examine the linked response and available trace information before suggesting a prompt or configuration change.
